# Limits and evidence

Read these limits with the [security model](security-model.md). Detection and reinjection are different operations: blocking a scrub failure does not mean every identifier in a successful request was detected.

- **Detection scope:** PHONE, BVN, NIN, ACCOUNT_NO, EMAIL and PERSON are supported. Context and formatting affect the structured rules; names use a gazetteer and optional local NER. Obfuscated, spelled-out or unfamiliar formats can be missed. Unknown request fields and unsupported content may pass through unchanged.
- **Evaluation:** [metrics.txt](metrics.txt) records a synthetic, project-authored regression set, not independent production evidence. PERSON recall is 96.9% and precision is 61.9% there; over-redaction is substantial. These figures do not establish performance on customer data or adversarial inputs. No new benchmark or quality measurement accompanies these guides.
- **Model availability and time:** NER can be disabled or fail to load at startup, leaving rules and gazetteer. Readiness remains unavailable if NER is configured on but not warm. Once inference is attempted, errors/timeouts block that request. Measure latency on your hardware; cold inference, cache hits, input size and load differ.
- **Session continuity:** reuse `X-Aegis-Session` within the same tenant and TTL window. Without it, each request gets a new Session. State loss can leave Placeholders in replies. Streaming holds incomplete Placeholders in a bounded buffer; a late failure after headers cannot become a new error status.
- **Data surfaces:** Wire Tap contains post-scrub requests, which may include detector misses. The Reinjector restores known Placeholders; it does not sanitize arbitrary new content generated by Upstream. Provider retention and client/chat-application storage are separate responsibilities.
- **Storage:** Redis persistence is disabled by the supplied configuration, but an existing SQLite audit file stores Telemetry Event fields. The in-process NER cache holds detected spans; Redis TTL is not a complete application-wide deletion promise. Audit-chain hardening is deferred. Do not place sensitive text in metadata fields.
- **Access and abuse:** tenant authentication is off unless `AEGIS_KEYS_FILE` is configured. The startup development bypass, CORS, and per-client rate limits are not substitutes for a protected deployment. The default Compose stack is local development only.
- **Playground:** opt-in, synthetic-only and scrub-only; no real model reply, restored reply or Telemetry Events. Its full/lite mode describes actual NER availability. Cleanup failure relies on temporary Redis expiry. No detection result makes a public demo suitable for personal data.
